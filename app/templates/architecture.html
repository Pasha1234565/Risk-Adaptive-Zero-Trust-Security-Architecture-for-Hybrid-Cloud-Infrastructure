Deliverable 1 · architecture design

Hybrid cloud zero-trust architecture

A shared policy plane evaluates identity, device, behaviour and resource context before any request reaches a private or public cloud workload.

Open API docs
01

Never trust, always verify

Network location grants nothing. Every request is authenticated and authorised on its own context.

02

Least privilege

Role, resource category and device posture determine the minimum viable access.

03

Assume breach

Anomalies are scored continuously; suspicious sessions are challenged, restricted or blocked.

04

Adaptive response

Risk is recalculated after step-up MFA, so access can recover without a new login.

Request lifecycle

From subject to adaptive outcome

  1. 1
    User / device request

    A subject requests a named resource in either trust zone.

  2. 2
    Authentication

    Password verification is PBKDF2-SHA256; interactive identities support TOTP step-up.

  3. 3
    Context collection

    Identity, device posture, geo-velocity, request rate, egress, session and threat intel are normalised.

  4. 4
    Anomaly detection

    The hybrid detector scores deviation from the behavioural baseline.

  5. 5
    Risk score

    Six weighted signals plus least-privilege policy escalation produce a 0–100 score.

  6. 6
    Policy engine

    Thresholds and policy minimums map risk to Allow, Challenge, Restrict or Block.

  7. 7
    Access decision

    The PEP releases data only for Allow/Restrict, masks on Restrict, and raises alerts for containment.

Deployment model

This is a single-host research prototype: FastAPI serves the console and APIs, SQLite stores telemetry, and scikit-learn holds the behavioural model in memory and on disk. The private/public split is modelled as explicit trust zones rather than separate cloud subscriptions, so the full architecture can be reproduced locally without cloud credentials. Production hardening would add a managed IdP, a shared policy store, TLS between components and an external SIEM.
